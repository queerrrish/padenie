# Журнал решений

Формат: дата, что решили, почему. Новые записи добавляются вниз.

## 2026-11-04

### Геймплей

Все решения ниже внесены в `DESIGN.md`.

- **Наклон не повторяет реальную физику один к одному.** При наклоне вбок шар смещается с ограниченной силой, падение продолжается. Почему: падение — основа игры, оно не должно пропадать от наклона.
- **Переход к откату.** При небольшом наклоне шар падает, ближе к горизонтали останавливается, затем начинается откат. Почему: так игрок успевает среагировать, а быстрый переворот становится навыком.
- **Откат чуть медленнее падения, на фиксированное расстояние.** Почему: откат должен быть платным ходом, а не способом свободно гулять по трубе.
- **Переворот доступен всегда.** Почему: иначе застрявший шар без зарядов встряхивания оставляет игрока только ждать конца таймера. Насколько он важен в середине этапа, ещё решается.
- **При движении вверх препятствия не ломаются.** Откат только меняет траекторию. Почему: разгон и пролом происходят при падении. Пункт обсуждаемый.
- **Телефон лежит плоско — игра полностью останавливается, включая таймер.** Почему: в таком положении игрок ничего не может сделать.
- **Скорость копится постоянно.** Почему: разгон — главное удовольствие игры. Может быть скорректировано после проверки.
- **Любое касание тормозит шар, сила зависит от предмета.** Почему: задача игрока — пролететь чисто.
- **Касание трубы снимает время.** Почему: это заставляет переворачивать телефон быстро.
- **Реакция на удар ниже порога и потеря скорости зависят от типа препятствия.** Почему: разные материалы должны ощущаться по-разному.
- **Преград внутри этапа нет, этап заканчивается концом отрезка.** Почему: внутри этапа главное — обход предметов.
- **Преграда с накапливаемой прочностью одна, в конце уровня.** Первоначально в `DESIGN.md` преграда стояла в конце каждого этапа. Почему накопление: откат идёт на фиксированное расстояние, и при одном только пороге повторные удары не помогли бы.
- **В конце уровня 1 остаётся решётка ливнёвки, лёгкие засоры из листьев могут быть в течение уровня.** Почему: нужно, чтобы было куда тратить ускорение, иначе к концу уровня у игрока всегда много бонусов.
- **Рестарт сразу, всё восстанавливается.** Почему: этапы короткие, повтор не должен раздражать.
- **Таймер идёт с начала этапа.** Почему: шар падает всегда, отдельного старта нет.
- **После этапа — статистика, звёзды и бонусы, затем новый разгон.** Почему: скорость не переносится между этапами.
- **Звёзды за скорость прохождения, с касанием максимум две.** Почему: оценивать и быстроту, и чистоту прохождения.
- **Уровень 1: прямая труба, немного торчащие предметы, которые легко обойти. Гнёзда и хомуты убраны.** Почему: начало игры должно быть простым, усложнение — дальше. Этап 1: листья, палочки, хвоя, дальше предметы крупнее.
- **При первом разе показываются подсказки.** Почему: игрок должен понять управление, в том числе переворот.

### Техника

- **Прототип: браузер, HTML и обычный JS, без сборки.** Почему: открывается на телефоне по ссылке, не нужна установка инструментов.
- **Физика: Planck.js, а не Matter.js.** Почему: скорость копится без предела, а препятствия тонкие. В Matter.js нет защиты от пролёта сквозь объекты на большой скорости, в Planck.js есть режим bullet.
- **Защитный потолок скорости в конфиге, заметно выше игровых значений.** Почему: страховка от сбоев физики, на игру влиять не должен.
- **Все параметры физики и баланса в `prototype/config.js`.** Почему: их можно крутить без чтения кода.
- **Наклон считается по углу поворота телефона в плоскости экрана (`devicemotion`).** Почему: это прямо соответствует `DESIGN.md`. Полный наклон и мёртвая зона вынесены в конфиг.
- **Запуск игры не ждёт полноэкранного режима и блокировки экрана.** Почему: при проверке такой запрос не ответил, и кнопка «Начать» зависала. Эти функции желательны, но не обязательны.
- **На телефоне есть отладочная кнопка «Заново».** Почему: на телефоне нет клавиши `R`. Это инструмент прототипа, а не геймплей.

### Процесс

- **Имя и почта для коммитов заданы только в настройках этого репозитория, почта служебная (noreply).** Почему: репозиторий публичный, а личная почта не должна быть видна в истории.
- **План из `ROADMAP.md` утверждён.** Почему: заказчик проверил этапы и согласился с ними.
- **Прототип открываем через GitHub Pages, репозиторий публичный.** Почему: постоянная ссылка с HTTPS, компьютер может быть выключен, а аккаунт GitHub уже есть. Цена: `DESIGN.md` и код видны всем.
- **Референсы лежат в `assets/references/`, а `prototype/` только для кода.** Почему: SVG `v1`–`v3` пока только референсы и в прототипе не используются.
- **Первый телефон для проверки — Android.** Почему: это телефон заказчика. iOS проверяем позже, на этапе 6, правила для него остаются в `CLAUDE.md`.
