# Падение: правила проекта

Заказчик — Houdini TD, не программист-геймдевелопер.
Решения объяснять коротко и по-человечески, общение на русском.

## Источник правды
- docs/DESIGN.md — единственный источник правды по геймплею.
- Если чего-то в нём нет, спросить, а не изобретать.
- Технические решения можно предлагать самому, с коротким обоснованием.

## Решения
- Все решения, принятые по ходу, записывать в docs/DECISIONS.md:
  дата, что решили, почему.
- Если решение меняет геймплей, обновить и docs/DESIGN.md.

## Параметры
- Все параметры физики и баланса — в одном файле prototype/config.js.
- У каждого параметра комментарий: что делает, единицы измерения,
  что будет, если увеличить.
- Числа в коде не прописывать. Временные значения помечать в комментарии.

## Порядок работы
- Маленькие шаги: каждый шаг — рабочее состояние, которое можно открыть и проверить.
- Коммит после каждого рабочего шага, понятное сообщение на русском.
- План этапов — docs/ROADMAP.md.

## Стек прототипа
- Браузер: HTML + обычный JS, без сборки и установки зависимостей.
- Физика: Planck.js (порт Box2D), копия библиотеки лежит в prototype/lib/.
- Для быстрого шара включать режим bullet, иначе он пролетит сквозь препятствия.
- На этапе прототипа графика — только простые фигуры.

## Управление и датчики
- Для отладки на ПК всегда должно работать управление с клавиатуры
  вместо акселерометра, включая переворот и плоское положение телефона.
- Акселерометр в браузере работает только по HTTPS.
- На iPhone разрешение на датчики запрашивается по нажатию кнопки.
- Знаки осей на iOS и Android различаются: проверять на обоих.
- iOS Safari не умеет фиксировать портретную ориентацию из кода:
  нужно предусмотреть поворот страницы и подсказку включить блокировку поворота.
- Проверка управления считается пройденной только на реальном телефоне.
